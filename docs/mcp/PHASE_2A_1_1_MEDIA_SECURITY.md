### Reproduced defect and correction: MED-A1 — uploaded SVG executes with application authority

Before refinement, a real multipart SVG upload through `/media/upload` and a real task-template featured-image upload both returned public files. Opening each URL through the actual Nginx proxy executed its inline JavaScript on the SPA origin. The script read a **synthetic localStorage sentinel** and wrote a marker. The victim session came from actual UI password login/backend JWT issuance. No customer file, actual credential value, external callback or exfiltration was used. This demonstrates that attacker-controlled uploaded documents could execute with the origin that stores application credentials; it is independent of whether those images are intended to be public or private.

Both cases are recorded as **EXPECTED_REPRODUCTION**, not security PASS: [before-fix browser evidence](../../backend/checks/phase1-5-cbeeee1a0f0a46918aa74fff6e3c7bcf/independent-uploaded-document-before.json).

The correction adds `Content-Security-Policy: sandbox allow-downloads` and `X-Content-Type-Options: nosniff` to local `/uploads` responses and `/assets/task_templates/*` responses. It does **not** allow scripts or same-origin authority. A shared [uploaded-media HTTP helper](../../backend/app/media_http.py) is used by the `/uploads` mount in [main.py](../../backend/app/main.py) and the task-template branch of [AvatarSafeStaticFiles](../../backend/app/avatar_http.py). Other packaged assets and the exact bundled-avatar allowlist retain their existing handling. Anonymous visibility, file locations and database records are unchanged. This is document-execution isolation, not a blanket private-file conversion or an authorization check. The behavior follows the [CSP sandbox directive](https://www.w3.org/TR/CSP3/#directive-sandbox).

After correction, both actual uploaded SVGs fail to execute/read the sentinel; both still render as16-pixel images, return their bytes successfully and complete native browser downloads. The sandbox header also survives HEAD,206 range and304 conditional responses in separate in-process HTTP tests. The header does not sanitize the stored bytes or retract already downloaded files, and does not protect an alternate storage/proxy host which omits it. Standalone PDF viewer/plugin behavior, all document formats and every browser engine were NOT RUN; download/image compatibility is the executed evidence, not universal preview compatibility.

## 6. Decisions and next-stage prerequisites

1. **Legacy media visibility:** identify which MediaItems, task/template attachment links, template images, badge/reward images and external assets are public/shareable versus private. Approve a per-category rule and a way to resolve mixed historical objects. Do not infer it solely from extension, path, uploader role or current public behavior.
2. **Immutable ownership:** decide whether media stays with the original tenant when an uploader transfers, how orphaned/deleted uploader assets are handled, and who can transfer ownership. Current uploader-derived tenancy is not an approved historical transfer policy. Department ownership remains global with incompatible String/UUID references; no Department backfill or migration is part of this phase.
3. **Chat/catalog sharing:** approve existing cross-tenant membership/global directory behavior and global templates/catalogs, or specify their tenant boundaries. Fix chat byte routing using authorized resource admission, not a public root mount.
4. **Private delivery:** approve compatibility behavior for existing copied links and external embeds. For confirmed private historical content, prepare an authenticated object-ID download path or intentionally authorized short-lived mechanism, update references, inventory old public copies, and stage provider/CDN policy changes with rollback. A route fix alone cannot revoke a public Drive grant, Supabase public object or CDN copy.
5. **Provider verification:** supply a disposable compatible server through an approved available distribution; test actual private/public buckets, direct access/listing, signature/key/method tampering,300-second expiration, deletion/replay and cache headers. Separately validate deployed policy through an authorized operational review without customer content access.
6. **Bearer limitations:** 300 seconds is retained as the existing bounded delivery policy. Do not promise immediate revocation of issued URLs, retraction of downloaded bytes, one-use PUT or freeze-after-confirmation. If required, design those semantics separately before live delegated access.
